# pi-pretty 0.6.25

## Summary

Brings oh-my-pi's signature motion to pi: the streaming `Working…` row and the hidden-thinking `Thinking...` label now shimmer with a traveling accent band — flush-left, per-session colored, and configurable — replacing pi's static chrome by default (both are one flag away from pi's defaults).

## What changed

- **Shimmer working indicator:** an accent band sweeps across the `Working…` text at 30 cells/second over a dim braille spinner, with the interrupt hint trailing. Pi's own loader row carries a built-in one-column indent that the frames API cannot change, so pi-pretty hides the host loader (`setWorkingVisible(false)`) and draws the row with its own zero-padding widget above the editor, animated at 30fps. `workingIndicator.text` accepts one phrase or an array (one full sweep per phrase, spinner phase continuous); `mode: "kitt"` swaps the sweep for a ping-ponging scanner head with a decay trail; `mode: "static"` renders one unanimated frame. Tier colors resolve `#rrggbb` hex, then the active pi theme color name, then built-in fallbacks.
- **Session accent tint:** the mid/high tiers and the spinner are tinted with a stable per-session color derived from the session name — a djb2 hue on a dark-safe arc, rendered at constant OKLCH lightness/chroma (oh-my-pi's session accent, ported to plain TypeScript; the theme-carrying cusp/WCAG machinery is intentionally skipped because pi does not expose theme internals to extensions). Different windows get different hues at uniform perceived brightness; renaming the session re-tints live.
- **Thinking-label shimmer:** with thinking blocks hidden, pi's static `Thinking...` label (italic `thinkingText`) gets the same sweep, tinted by the session accent. The only extension lever (`setHiddenThinkingLabel`) rebuilds chat children, so the animation runs at 30fps **only while the streaming message is actively emitting a thinking block** and restores pi's default label the moment text or tool calls stream, when the run ends, or when thinking visibility is toggled.
- **Config:** new `workingIndicator` block (`enabled`, `text`, `mode`, `low`, `mid`, `high`, `bold`, `hint`, `sessionAccent`) and `thinkingIndicator.enabled`, plus `PRETTY_WORKING_INDICATOR`, `PRETTY_WORKING_INDICATOR_MODE`, `PRETTY_WORKING_INDICATOR_TEXT`, and `PRETTY_THINKING_INDICATOR` env overrides (env > config > default).

## Behavior change

Both indicators are **on by default**. To go back to pi's stock chrome:

```json
{
	"workingIndicator": { "enabled": false },
	"thinkingIndicator": { "enabled": false }
}
```

## Why

- The static `Working...` row wastes the highest-attention line in the TUI; oh-my-pi's shimmer makes state legible at a glance (is the agent idle, thinking, or writing?) without reading anything.
- Per-session accent colors make multiple concurrent pi windows distinguishable at a glance.
- The working row had to be widget-owned because pi's `Loader` hardcodes `Text` padding of 1 column; the thinking label rides pi's own label API (`setHiddenThinkingLabel`) with a phase-gated 30fps ticker so the transcript rebuild cost is bounded to the thinking phase.
