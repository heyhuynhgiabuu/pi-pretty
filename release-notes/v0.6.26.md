# pi-pretty 0.6.26

## Summary

Per-message hidden-thinking labels that keep their own elapsed durations (each completed message freezes as `Thought for Xs` while the streaming row animates), a live token counter on the working indicator, and two visual fixes: tool titles now sit flush against their content, and the extension loads through `src/index.ts` so host SDK aliases always apply.

## What changed

- **Per-row hidden-thinking labels:** pi-pretty intercepts the host's per-row label fan-out (`AssistantMessageComponent.prototype.setHiddenThinkingLabel`) so the streaming row animates `Thinking... Xs` while completed rows stay frozen at their own `Thought for 12s` instead of every row mirroring the latest write. Durations live for the current session (not persisted across restarts). A message with several thinking runs (interleaved `thinking → text → thinking`) shares one label line per run; those runs accumulate a single per-message total — a later run resumes the count instead of rewinding to zero. If the host class is missing or reshaped, the intercept falls back to pi's global-label behavior. The 30fps ticker runs only while the current message's last block is thinking.
- **Live token count:** the working indicator row appends ` (↓ 1,234 tokens)` while streaming (provider usage when available, characters÷4 estimate otherwise), styled dim, throttled to one update per second.
- **Entry through source:** the package manifest now points pi at `./src/index.ts`. jiti loads `.ts` entries through its alias table, so the extension always binds to the running host's `AssistantMessageComponent`; a `.js` entry natively imports and, in a checkout with its own SDK dependency, binds a *different* class — which made every completed row mirror the active timer. The Node package entry (`main`) remains `dist/index.js`; managed npm installs keep working (both entries covered by loader tests).
- **Tool titles flush:** no blank row between the title and the result across `bash`, `read`, `find`, `grep`, and `ls` — collapsed, expanded, error, skill-read, and async-highlight paths. Top padding and result-body/footer spacing are unchanged. Host `edit`/`write` renderers never had this padding and are untouched.
