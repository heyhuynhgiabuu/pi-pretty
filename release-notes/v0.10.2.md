## Added

- **Turn off the FFF index** ([#28](https://github.com/heyhuynhgiabuu/pi-pretty/issues/28)). Set `"fff": { "enabled": false }` in `pi-pretty.json`, or `PRETTY_FFF=0` (the environment variable wins over the config file). When off, pi-pretty never loads the native FFF module, so no index or file watcher starts, and `find` / `grep` use Pi's built-in search. In a directory with millions of files the index could take hundreds of MB per Pi session.

## Notes

- There is no CLI flag for this. Pi 1.6 applies extension flag values only after extensions load and forces boolean flags to `true`, so a `--pretty-fff=false` flag could not work. The same timing means `--pretty-fff-home-scan` / `--pretty-fff-root-scan` currently have no effect; use `PRETTY_FFF_HOME_SCAN` / `PRETTY_FFF_ROOT_SCAN`.

### Verification

- `npm run typecheck`, `npm run lint`, `npm run build`: exit 0.
- `npx vitest run`: 384/384 pass, also with `PRETTY_FFF=0` in the environment.
- Not measured: actual memory saved in a large directory.
